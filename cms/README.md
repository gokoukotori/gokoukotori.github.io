# ローカルCMS

プロジェクトのルートで `npm run cms` を実行し、`http://127.0.0.1:5174/cms/` を開きます。
Node.js 24で検証しています。ポート変更は環境変数 `CMS_PORT` で指定できます。

## 編集とプレビュー

- アバター：素体 → テーマ → バリエーションを追加・編集・削除。上下ボタンで表示順を変更。
- 改変テーマ：「複製」で編集中の内容と配下のバリエーションをまとめてコピーし、同じ素体の元テーマ直後に追加して選択。名前には「（コピー）」が付き、説明・使用商品・写真の選択・三面図も引き継ぎます。コピー先の編集は元テーマに影響せず、画像ファイルは共用します。「ローカル保存」で確定します。
- 素体：任意項目の「URL」に http:// または https:// のURLを設定すると、素体ページの BASE AVATAR にリンクを表示。空欄では非表示。
- 使用商品：テーマ・バリエーションの各商品行にある上下ボタンで並べ替え。「ローカル保存」で確定し、紹介ページにも設定順に表示されます。
- バリエーション：使用商品、任意の三面図、関連フォトを設定。三面図は「画像を追加」または「URLで追加」で複数枚登録でき、画像ごとに説明・変更・解除、上下ボタンで並べ替え。公開ページでは設定順に表示。関連フォトはドラッグまたは左右ボタンで並べ替え。
- バリエーションの「追加メイン画像」：「画像を選ぶ」で複数選択し、左右ボタンで並べ替え、×で解除。大きな画像エリアは代表写真が1枚目、その後に追加画像が続きます。1枚だけなら従来の表示、複数枚なら画像枠を縮めず下部に重ねた横並びサムネイルで切り替えられます。別のバリエーションに移ると代表写真に戻ります。関連フォト・三面図とは独立した設定です。
- メディア：JPEG / PNG / WebP（静止画、1枚25MBまで）を複数追加。撮影日時・ギャラリー掲載・使用先を確認。
- アバター紹介のサンプル注記は、アバター管理で切り替え。
- ローカル保存後、CMS内のプレビューリンクで確認。保存前の内容は `.cms/backups/` に保存し、最新10件を保持。保存成功後に古いバックアップを削除します。

管理対象はギャラリー画像とアバター一覧です。Homeの表示名・自己紹介・外部リンクなどはCMSの編集・保存対象に含みません。

編集内容は `site/src/data/content.json` に保存します。既存237枚の `gallery.json` は元の台帳として保持し、追加画像と掲載設定を合成して表示します。従来の237枚用スクリプトをCMSの追加画像に対して実行する必要はありません。

新規画像は `.cms/media/` に元画像・表示用画像・サムネイルを保存します。表示用は長辺最大3840px、サムネイルは最大640px、sRGBのWebPに変換し、拡大やトリミングは行いません。既存画像は再変換しません。VRChat形式のファイル名では撮影日時を抽出し、それ以外ではファイル更新日時を初期値にします。

R2には元ファイル名の拡張子を `.webp` にした名前で保存します（例：`media/display/写真.webp` と `media/thumbnails/写真.webp`）。未アップロードの既存画像もこの方式で送信し、保存後に参照URLを更新します。公開済み画像のURLは変更しません。同じ保存名の別画像はエラーとし、上書きしません（`写真.png` と `写真.jpg` も同じ保存名になります）。ローカルの実ファイルは引き続きハッシュ名で管理し、元ファイル名は `originalName` に保持します。

新規画像は初期状態でギャラリー非掲載です。代表写真・追加メイン画像・三面図には非掲載の画像も選択できます。関連フォトには掲載中の写真を使います。非掲載はギャラリーから外す設定であり、画像URLのアクセス制限ではありません。

未アップロードで未使用の画像は、取り込みを取り消せます。登録情報と、CMS内に保存した元画像・表示用画像・サムネイルを削除します。取り込み元のファイルは削除しません。

## 公開

1. ローカル保存してプレビュー。
2. 「プレビュー・公開」で対象を確認してR2へ画像をアップロード。既存キーは上書きせず、保存後にサイズとハッシュメタデータを照合します。
3. 「公開用ビルドを作成」。未アップロード画像が残っている場合は通常の `npm run build` も停止します。
4. 差分を確認して通常のGit操作でコミット・mainへプッシュ。既存のGitHub Actionsで公開されます。

CMS自身はコミット・プッシュを実行しません。管理画面・API・`.cms/` は公開用distに含まれません。

R2の認証情報は既存の `.env.r2.local` を使用します。

```text
GALLERY_R2_ACCESS_KEY_ID=...
GALLERY_R2_SECRET_ACCESS_KEY=...
# 任意（既存の値が既定値）
GALLERY_R2_ACCOUNT_ID=...
GALLERY_R2_BUCKET=home-gallery
```

認証情報はサーバーだけで使用します。CMSは127.0.0.1に限定し、保存APIは同一Originと起動ごとのトークンで保護します。
`.cms/` はGit管理外です。ローカル元画像と保存前の控えが入るため、必要に応じて利用者側でバックアップしてください。

## 検証

`npm run test:cms` / `npm run test:avatars` / `npm test` / `npm run build`

CMSテストはプロジェクト内の一時コピーで実行します。R2テストは模擬ストレージを使用し、実バケットに送信しません。
